## 2. 覆盖与结论范围（R02）

**冻结的条件可配对率不变**：分子是 complete + unbounded，分母是 matured_missing_result + entry_missing + unpriced + unbounded + complete。

**新增 collection_pending 类：** as_of 当天没有机会行、且当日采集窗口未结束时，记这一类，不算漏采。窗口结束的定义是 09:30 ET，因为准入要求 `recorded_at` 早于 09:30 ET，此后不可能再出现合格行。运行时刻未知时，按窗口未结束处理。

**新增全日历覆盖（描述，不是闸门）：** 每级都给原始分子和分母：

| 项目 | 分子 / 分母 |
|---|---|
| 采集 | 生成了机会行的日数 / 应采集日数（总日数 − collection_pending） |
| 身份可审计 | 身份合格 / 已生成 |
| 有方向 | 有方向 / 身份合格（无方向是预定义弃权，不是亏损） |
| 有候选 | 有候选 / 有方向 |
| 成熟有结果 | 已成熟且有结果 / 已成熟 |
| 端到端可配对 | complete + unbounded / 应采集日数 |

- **工程缺失** = not_generated + identity_fail + matured_missing_result。
- **完整性：** 应采集日为 0 时记 empty；否则工程缺失为 0 记 complete，大于 0 记 incomplete。

**适用范围：** 每项假设的判定都附两句话：
- **条件结论：** 只对身份合格、有方向、有候选、已成熟且可配对的样本成立。
- **推广：**
  - 完整性为 empty 时，写「未决（尚无应采集日）」；
  - 完整性为 complete 时，写「覆盖完整」；
  - 否则写「未决：工程缺失 N 格，缺失敏感性分析未做」。
  - 理由：工程失败可能与剧烈行情、数据源拥堵相关，不能假定它与收益无关。

完整性为 incomplete 时，「支持 / 统计为正 / 不支持 / 排除」这几类判定字符串末尾附「［条件样本内；全日历推广未决］」，让范围随判定一起出现，单独转述时也不会丢。

**没有新增覆盖门槛。** 将来若要把覆盖率设为正式闸门，必须先说明它保护哪个目标总体、阈值为什么这样选，并发布新版本。不能为了让既有检验通过去调门槛。

## 3. 新增描述：共同可界定样本的计价包络（不参与判定）

**取键：** 对 B1 和 A 各做一组，取 P、C 两侧都有上界的日期。连上界都没有的，记入 `n_unpriced`，不伪造数值。

**绝对收益：** 对顺向、逆向、总是卖 put、总是卖 call 四个序列，各给三组区间，每组都是 [按下界, 按上界]：
- 均值；
- 胜率：下界为 L>0 的比例，上界为 U>0 的比例；
- 最差 k 个的均值，k = max(1, ⌊n×10%⌋)。

任一下界未知时，保守侧记为未知，不以 0 补齐，并给出下界未知的个数。

**相对效应：** 逐日按 [L_x − U_y, U_x − L_y] 传播后取均值，任一端未知则该端未知。**两个上界相减既不是上界也不是下界。** Codex 的反例：X∈[0,10]、Y∈[−100,20]，上界相减得 −10，但 X−Y 实际可到 110，正确区间是 [−20,110]。

**性质：** 这是确定性的计价界，不是统计置信区间。主检验「有无界配对即未决」的规则不变。

**措辞更正：** 我在 011 回信里说「未知残腿恰好集中在反向大幅波动日」，这是**待检验的机制假设**，不是已观测事实。真实样本为 0 时不能这样写。将来可以按事后幅度与缺失原因做描述性分层，但不能反过来用于事前择时。
