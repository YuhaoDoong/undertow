## 1. F01：有结果对象，不等于收益可评估

**v1.2 的问题：** 工程缺失只算了漏采、身份失败、成熟缺结果三类。入场缺报价（entry_missing）和未定价（unpriced）没算进去。Codex 的合成例是：67 日全部生成，34 日可计价，32 日入场缺报价，1 日有效弃权。v1.2 对这个例子的输出是：
- 成熟有结果 66/66；
- 完整性 complete；
- 判定「支持」，不带范围后缀；
- 推广写「覆盖完整」。

**v1.3 把覆盖拆成两件事：**

| 项目 | 含义 |
|---|---|
| 记录完整性 | 缺口 `record_gaps` = 漏采 + 身份失败 + 成熟缺结果 |
| 收益可评估性 | 缺口 `return_gaps` = 成熟机会里收益**不是点值**的格数，分项列出：入场缺报价、未定价、无界、有限区间、缺结果 |

**字段改名：**
- 原来的「成熟有结果」改名为 `matured_result_object_present`，只表示有结果对象。
- 新增 `matured_return_identified`（点值数 / 已成熟数）和 `matured_return_breakdown`。

**完整性状态：**

| 状态 | 条件 |
|---|---|
| empty | 应采集日为 0 |
| incomplete | 两类缺口任一大于 0 |
| no_matured | 无缺口，但尚无已成熟机会 |
| complete | 两类缺口都为 0，且有已成熟机会 |

- **推广：** 只有状态为 complete 时，才写「覆盖完整」；其余状态都写「未决」，并分项列出缺口。
- **判定串：** 状态不是 complete 时，「支持 / 统计为正 / 不支持 / 排除」这几类判定串末尾都附「［条件样本内；全日历推广未决］」。

**入场缺报价的处理：** 入场缺报价的原因目前无法区分：可能是任务没跑，可能是数据源故障，也可能是可观测的流动性不足。所以一律按「收益未知」计，**不事后改称弃权，也不当作零收益**。

v1 起就没有预先定义的流动性弃权规则，所以本版不单列「可确认的执行弃权」。若将来要加，必须先写成新的预登记版本，写明判定所用的原始报价证据，并在看到结果之前冻结。

**无界：** 无界配对仍留在冻结配对率的分子里，但不算收益已完整识别。主检验遇到无界就判「未决」的规则不变。

## 2. 说明（不改公式）

- **胜率下界：** 收益下界未知时，均值与最差 k 均值的保守侧都保持未知。但胜率是二元事件，下界未知的那条可以最坏按「不赢」计，所以胜率下界仍可以算出来。这是胜负的逻辑下界，不是把收益补成 0。
- **相对区间偏宽：** 同一日期、同一实际腿相比时，真实差值本应是 0。通用的区间减法会给出一个包含 0 的较宽区间，这是保守的结果，不是错误。
- **采集待定：** collection_pending 以当日 09:30 ET 为研究采集截止，Codex 013 同意。运行时刻未知时，报告注明「运行时刻未知，按窗口未结束处理」。研究口径上的「待定」**不压住运维告警**：任务失败、未唤醒、没有有效产出，仍由任务状态文件和 FAILURE 兜底文件即时报告，两者互不影响。
