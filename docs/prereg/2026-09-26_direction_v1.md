# 预登记：方向次要分析 dir-analysis-v1

**冻结时刻：** 本文件随提交入库的时刻（git 提交时间）。该时刻早于首个纳入样本 2026-09-28 的盘前采集。
**作者：** Claude Code / Opus 5.5（实施），设计来自 Codex/GPT-6 009/010 审查，论点来自用户。
**基础实验：** shadow-v5-20260926，配置哈希 `9e60a71ac3cec0f3`。本分析**不改 v5 的任何东西**，包括选腿、入场、退出、主终点、样本准入与主比较 A−B1。
**机器可读版本与哈希：** 同目录 `2026-09-26_direction_v1.json`。守卫测试 `tests/test_prereg_freeze.py` 保证：改动冻结的代码而不升版本时，测试失败。

## 1. 用户原话（原样）

> 现在模块中是否还没有引入方向性的判断？
> 我之所以觉得这是个可行策略，是因为这个策略可以大幅度提高方向性交易的胜率。
> 绝大多数交易策略其实都是方向性的，期权墙可以提高方向性的准确率，而方向性可以提高卖方价差的胜率（之前我们回测是随机方向吧？），而卖方价差又可以反过来提高方向性交易的胜率，因为只要不要出现大幅度反方向即可盈利。
> 我觉得这三者都是要结合在一起的。

## 2. 定义

**Y：** v5 主终点 `pre_expiry_exit_policy`（到期前最后交易日收盘窗的退出政策）的「净损益 ÷ 事前最大风险」。
- 区间值按 v5 规则：只买回短腿时，残腿到期虚值为点值，实值时处置未知、下界 None。
- 配对差按 [x下界 − y上界, x上界 − y下界] 传播。任一下界未知的配对记为「无界」，含有无界配对的判定为「未决」。

**A：** v5 的墙选腿。取 ≤14 天、±5% 带内该侧累计 OI 最大的档（local_max）作为卖腿，同美元宽度配保护腿。

**B1：** v5 的主对照。按 `analyze.shadow.pick_b(mult=1.0)` 选腿：
- put 侧取 ≤ 决策价 − 1.0×ATR14 的最高挂牌档，call 侧取 ≥ 决策价 + 1.0×ATR14 的最低挂牌档；
- 保护腿为卖腿 ∓ 统一美元宽度（2 × ±5% 带内众数行权价间隔），不挂牌则不可配对；
- 决策价为 T 之前最后一个日线收盘，ATR14 用到该日为止的日线。

注意：B1 不是「与墙同距离」的对照，所以 A−B1 只能解释两条规则的整体差异，不能单独归因为墙的因果作用。

**方向信号（唯一）：** `decision.flow.call_direction`，即持仓流方向。
- **来源：** 首份冻结的信号台账 `data/history/signals/<品种>.json`，由前一日与当日两份盘前快照的持仓变化确定性算出。算法为 `analyze.flow.probe_strong_signal`，代码哈希冻结在 JSON 里。
- **映射 dir-map-v1：** 偏多 → 顺向侧 a = P（卖 put 价差），逆向侧 o = C；偏空 → a = C，o = P；其余（中性、缺失）为无方向，只进分母，不补成看多或看空。

**时间契约：**
- 每行采集时记录 `available_at`（两份快照中较晚的抓取时刻）、两份快照的文件哈希、台账行哈希、算法代码哈希和映射版本。
- 纳入要求：`available_at` < 该行 `recorded_at` < 当日 09:30 ET，且 session 已认证，即沿用 v5 的 `prospective_ok`。
- 文件名日期本身不作为时间证据。

**纳入样本：**
- 起点：session ≥ **2026-09-28**，更早的回放行一律不进。
- 品种：主池七个 ETF（gold silver wti qqq tlt spy iwm），**分别检验，不合并**。杠杆 ETF 与个股只作描述。
- 正式检验日：**2026-12-31**。之后的第一次运行才是正式判定，只收 session 与全部候选腿到期日都 ≤ 该日的行。此前一切输出都标「探索」。

## 3. 假设（只有这两项参与判定）

| 编号 | 配对（同品种、同日） | 回答的问题 |
|---|---|---|
| H-dir | Y(B1, a) − Y(B1, o) | 固定距离选腿时，按方向选边有没有价值 |
| H-wall\|dir | Y(A, a) − Y(B1, a) | 顺向交易里，墙选腿是否比距离规则更好 |

**多重比较：** 2 项假设 × 7 个品种 = 14 个检验，构成独立的次要家族。单侧 α = 0.05/14 ≈ 0.00357。这不等于全项目的族错误率已被控制。

**区间：** 沿用 v5 的循环移动块 bootstrap：按日历交易日滑动，块长 5 日，20000 次，种子 20260926。有样本的日期数 ÷ 5 ≥ 4 时才出区间，常数样本判为退化。单侧下界取 α 分位，上界取 1−α 分位。

**判定（每个品种、每项假设）：**

| 结果 | 条件 |
|---|---|
| 证据不足（工程/数据） | 可配对率 = (配对 + 无界配对) ÷ 有方向机会 < 0.5 |
| 未决（残腿处置未知） | 存在无界配对 |
| 证据不足（配对日期不足） | 有配对的日期 < 20 |
| 支持 | 单侧下界 > 经济门槛 δ = **0.03** |
| 统计为正、未达经济门槛 | 0 < 下界 ≤ δ |
| 不支持 | 上界 ≤ 0 |
| 未决 | 其余情况 |

δ = 0.03 **未校准**：约等于多付一次往返费用（$3.20）占典型最大风险（约 $80–180）的量级。它是研究选择，不是市场规律。

**H-dir 通过，不代表 H-wall|dir 通过；反之亦然。**

## 4. 描述性内容（不参与判定、不宣称显著）

- **交互：** [Y(A,a) − Y(B1,a)] − [Y(A,o) − Y(B1,o)]，看墙的增量是否集中在顺向侧。
- **四个格子的点值：** B1 与 A 的顺向、逆向各自的均值、胜率、最差 10% 均值。只计点值，区间值和无界单独计数。
- **固定侧基准：** 同样本上「总是卖 put」「总是卖 call」的 B1。用来防止「方向信号几乎总看多」只是在复述本期的上涨。
- **直接做方向：** 入场窗到到期前一交易日收盘窗的标的变动，与方向是否一致。标的价取两个窗口里记录的长桥实时价，只列符号命中率，与价差的损益/风险单位不同，不可直接比较。
- **完整性：** 行数、有方向/无方向、看多/看空、配对数、无界数。

## 5. 探索标签（只记录、不判定；以后实现时各自带版本号）

各标签只能用信号可用时刻之前的数据计算（日线截止到 T−1 收盘），缺失保持未知：

- **综合研判方向：** 首份冻结的 `outlook_scores.json`[品种][快照日] 的符号。该条目没有逐条写入时间戳，所以**时间身份未认证**，只能作为探索。
- **趋势：** C[T−1] 相对 SMA20 的符号；C[T−1] 相对 SMA200（牛熊）。
- **拉伸度档位：** `analyze.stretch.analyze_stretch`，用 T−1 为止的日线。
- **墙不对称：** 决策价到 A 的 put 墙、call 墙的 ATR 距离比；两侧墙的 OI 比。
- **gamma 代理：** 静态 OI × 模型 gamma 的有符号合计。它是**假设下的代理**，不能识别做市商的真实净持仓。

**禁止事项：** 看到哪个标签有效，就把它换成主方向信号；在 2×2 的各个子集里挑显著的结果；加入「三者一致才开仓」之类的新闸门。任何新规则都必须写成新的预登记版本，并在看到结果前冻结。

## 6. 通过与失败的分类

- **工程失败：** 可配对率不足、机会分母里出现无法解释的缺失。先修数据链路。
- **证据不足：** 样本或日期不够，既不说有效也不说无效，继续记录。
- **经济性失败：** 相对比较为正，但绝对收益为负、尾部更差或未达门槛。此时不能称策略已获盈利支持；H-dir 为正而两侧都亏损，同样属于这一类。
- **方向有效而墙无增量：** 策略改称「方向性卖方价差」。墙若仍参与选腿，写成「采用墙位选腿，增量未证实」。

## 7. 已知局限（与结论同时呈现）

- **影子报价不是实际成交。** 用的是两个固定窗口的保守盘口，没有连续盘中路径。
- **方向信号依赖推断。** 它来自隔夜 ΔOI 推断的买卖方向，与 Pan & Poteshman（2006）直接观察到的买方新开仓订单不同。
- **方向和墙不是独立的两票。** 两者来自同一份持仓数据，不能把两者的命中率相乘。
- **样本期短。** 2026-09-28 至 2026-12-31 只有一个样本期，市场状态单一。金银日收益相关约 0.89，跨品种不能当作独立证据。
- **券商执行性未核实。** 垂直价差的实际保证金、组合单能否单腿退出、行权与指派费都未知。

## 8. 修订规则

- **需要新的预登记版本并重新冻结：** 改信号算法、映射、配对定义、门槛、α、家族、纳入起点或检验日。已看过的样本只能作为探索。
- **可以只改文案、不升版本：** 纯粹的错别字或文案修正，但要在本文件末尾追加修订记录。
- **`analyze/flow.py` 的整文件哈希也被冻结，因为方向信号由它计算。** 它因无关原因改动时，要先确认 `call_direction` 在已记录样本上逐行不变（附比对结果）：
  - 不变：追加修订记录并更新哈希，不升版本；
  - 有变化：升预登记版本，旧样本只作探索。
