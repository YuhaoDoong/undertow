# 设计草案 v0.1（待 Codex 审，未冻结，未计分）：方向信号选侧对卖方价差的增量

v0（`e6d49e8`）原样保留，本文件按 Codex 019-06 修订。未改动的部分沿用 v0。

## 1. 时序资格（019-06 的关键点）

- **v5 的实际时序**（代码核实）：
  - 盘前 `shadow capture` 为 P、C **两侧同时**锁定候选，锁定时不使用任何方向信号；
  - 方向台账 `dirledger record` 与 `conviction-record` 在其后记录；
  - 入场报价由盘中 09:45–13:00 的采样取得。
- **一个机会可纳入的条件（全部满足）：**
  1. 所用信号的正式记录 `recorded_at` ≤ 所选那一侧的入场报价采样时刻。
  2. 信号输入快照的 `captured_at` ≤ 信号的 `recorded_at`。台账 v2 的身份检查已保证这一条。
  3. 两侧候选的锁定时刻都早于信号，且锁定过程与信号无关（v5 两侧照常生成）。
  4. P、C 两侧使用同一 entry 规则、同一采样窗口；某一侧缺入场报价时，该机会标为「不可比」，不补齐。
- 「信号在开盘前」本身不构成资格，必须与实际采样时刻逐条连接校验。

## 2. 结果口径

- **主口径：**v5 的 `primary_basis = pre_expiry_exit_policy`，止损按 v5 主规格，费用为每组往返 $3.20，已在净损益中扣除，**不重复扣**。
- **敏感性：**持有到期的结算口径，单独标注为「结算」，**不描述为按 bid/ask 提前平仓**。
- **单位：**R = 净损益 ÷ 该侧事前最大亏损（含费）。

## 3. 统计量与同时报告的指标

- **主统计：**有信号的机会上，Δ = R_chosen − (R_P + R_C)/2。衡量纯选侧效果。
- **必须同时报告：**
  - E[R_chosen]：方向政策自身的绝对期望。Δ > 0 可能只是「比两侧平均少亏」。
  - E[(R_P+R_C)/2]；
  - 尾部：R_chosen 最差的 5%；
  - 覆盖：可比机会数、不可比原因的分布；
  - 同一日期的机会数。
- **权重：**先在日期内对各品种取等权平均，再对日期取等权平均。同一天的多个相关 ETF 不算多次独立机会。
- **推断：**在交易日轴上做移动块 bootstrap，块长 ≥ 最长持有期的 2 倍（v5 的 DTE 上限为 4，块长定为 10）；每次重抽重算 B0 与 Δ。
- **α 族：**本研究单独成族，不占方向台账族 D 的 7 个名额。若正式声明，单侧 α = 0.05，主检验只有 Δ 一项。

## 4. δ* 与约束（在开发期定出，不看未来盈亏）

- **δ*：**不采用 v0 举例的 +0.05R。
  - 开发期（v5 前瞻起点 2026-09-28 之后的若干周）只分析：报价宽度、同步采样误差（同一桶内两侧报价的时间差）、费用占权利金的比例、缺价率。这些只用入场时刻可见的量，**不用任何结算结果**。
  - 由此得到 R 单位下的误差预算，δ* 取「预算上界」。只能得到区间时，做敏感性分析，**不伪造精确成交误差**。
- **最低独立日期数、尾部约束（例如最差 5% 的 R 不劣于基准）、资金约束（同一天重叠机会占用的保证金 ≤ 账户风险上限）：**待开发期结束时连同 δ* 一起冻结。
- **冻结之前不计分。**

## 5. 结论边界

- 通过：说明「在 v5 这套结构下，按该信号选侧，净收益改善不小于 δ*」。**不等于**信号本身的方向命中率高，也**不等于**所选策略的绝对收益为正（后者看 E[R_chosen]）。
- 未通过：不能推出「方向信息无用」。可能是 v5 结构把方向信息稀释了。
