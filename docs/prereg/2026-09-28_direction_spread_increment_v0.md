# 设计草案 v0（待 Codex 审，未冻结，未计分）：方向信号选侧对卖方价差的增量

**来源：**Codex 018 执行规划的顺序 3。它认为这一步「比再找一个历史高命中指标更接近用户要的结果」。
**用户原话：**「我们的卖墙价差策略，应该属于高胜率，高频率，低盈亏比的三角……现在我们迟迟没有的就是方向性判断。」
**基础：**影子账 v5（`shadow-v5-20260926`，已冻结）。它对每个机会已经**同时生成 put 与 call 两侧**候选（`CONFIG["sides"] = ["P", "C"]`），并且有采样、报价与结算。本研究只在 v5 的记录之上做离线连接，**不改 v5、不新增实盘执行**。

## 1. 研究问题

对同一个交易机会（同一品种、同一决策日、同一到期规则、同一墙位 / 宽度规则、同一进出时刻与费用口径），问：
- 按冻结的方向信号选择一侧；
- 与「不使用方向、两侧等权」的基准相比，

费用后的净收益（按事前最大风险归一）是否更高？

**要比的是净收益，不是方向命中率：**方向判对了，价差也可能亏；方向判错了，价差也可能赚。

## 2. 机会与候选（全部取自 v5 的冻结记录）

- **机会：**品种 × 决策日。put 与 call 两侧的 A 规则候选都通过 v5 的报价质量与采样资格。
  - 只有一侧合格时，标为「不可比」，不补齐；报告覆盖率。
- **单侧结果：**R_side = v5 结算的净损益 ÷ 该侧事前最大亏损。
  - 净损益按保守 bid/ask，扣双边费用；
  - 最大亏损为宽度减权利金，含费。
  - 这些都是报价估计，不是成交。
- **基准政策 B0：**(R_P + R_C) / 2。它表示不使用方向时的期望；**并不代表现实中会同时下两笔**。
- **方向政策 B1：**信号看涨选 put 侧，看跌选 call 侧；无信号记为不交易，R = 0，并单独报告。

## 3. 信号（事前冻结，二选一，或在同一族内都登记）

- **skew-reading-v1：**防守化看跌，进攻化看涨。台账 v2 的正式 eligible 记录。
- **conviction H1：**冻结之后的版本；开发期记录不可用于确认。
- 信号必须在决策日开盘前冻结。只使用 v2 截止政策下的 eligible 行。

## 4. 统计量

- **主统计：**在有信号的机会上，Δ = R_chosen − B0。这衡量「纯选侧」效果，与「是否交易」的择时效果分开。
- **次统计（描述）：**全部机会上，政策 B1（无信号记 0）与「总是按 B0 交易」的差。它混合了择时与选侧，只作描述。
- **同时报告：**
  - 尾部：最差 5% 的 R；
  - 费用消耗占毛收益的比例；
  - 同日多品种的重叠风险：同一天有 k 个相关机会时，按日聚合，不按 k 次独立机会计。
- **推断：**按决策日聚合；在完整交易日轴上做移动块 bootstrap，块长 ≥ 2 倍的最长持有期，同一日的所有品种一起抽。每次重抽同时重算 B0 与 Δ。

## 5. 通过、未决、失败（数值在冻结时写死，不由检验收益反推）

- **通过：**冻结后的新样本上，Δ 的单侧下界 > 0（按族内分配的 α），点估计 ≥ 最小有用改善 δ*，尾部与资金约束也通过。
- **未决：**区间跨过 0，或有效日期簇太少。
- **失败：**区间上界 < δ*，即该版本没有足够的实用增量。**不能换规则后重用同一批确认样本。**
- **δ*：**待开发期结束后，由报价不确定性与费用估计给出（例如每单位风险 +0.05R），**现在不定**。在 δ* 冻结之前，不得开始正式计分。

## 6. 依赖与待办（按顺序）

1. 核实 v5 记录里两侧候选的实际覆盖率（开发期可以查看覆盖与缺失，但**不看收益**）。
2. 实现离线连接器 `scripts/dir_spread_join.py`：只读 v5 与方向台账，输出每个机会两侧的 R 与信号。先在合成数据上测试。
3. 开发期的成本与报价误差分析，用来确定 δ*。
4. 送 Codex 审阅，然后冻结。**正式起点不倒填。**

## 7. 已知局限

- 影子账的报价是 CBOE 延迟快照与长桥采样，不是成交；小账户实际还受保证金与合约数量整数约束。
- 两侧的墙距离与权利金不对称，所以 B0 不是「风险中性」的基准。另要报告两侧事前风险之比的分布。
- 方向信号本身尚未验证。本研究同时检验「信号」与「选侧有用」两件事；结果为负时，分不清是哪一个没用。
