# 资金流「买卖方推断」验证 v0（预登记；写于任何结果之前；探索，不改冻结的方向族 D）

## 0. 用户原话

> 资金流分歧怎么验证？为什么我们认为call 增仓是偏多，他认为是卖call。买卖方向看不到吗？这个资金流，我们的是ETF 的期权资金流吧，他的是COMEX？

> 1 做一下。

## 1. 要回答的问题

conviction F 层与 structure_read 用同一行权价的相对 IV 变化（`delta_adj_pp`）推断买卖方：增仓且相对 IV 升 → 推为买方，相对 IV 降 → 推为卖方。这个推断是否与**当天实际成交的主动方**一致？

免费数据里看不到主动方：OI 变化只说明多了一份合约，每份合约同时有买方和卖方；交易所的开平仓数据按客户类型拆分，是付费的。所以只能用成交价相对报价的位置来近似判断主动方。

## 2. 单位与数据（均为 GLD / SLV 的 ETF 期权）

- **单位**：交易日 X 的合约 (到期, 行权价, C/P)，取 F 层实际计入的腿，即 `grade_leg(c).counts` 为真、行权价在现价 ±5% 内、纯净度已知。
  - 腿列表：由认证到 X 与 X+1 的两份快照，经 `analyze_flow` 得到 `fa.changes`，再逐条调用冻结的 `grade_leg` 计算；到期日取自 `fa.changes`。冻结代码不改。
- **推断方向**：`delta_adj_pp > 0` → buy，`< 0` → sell（call 与 put 同一口径，都表示该期权的买方或卖方）。
- **成交数据**：`option_intraday` 在交易日 X 的逐分钟成交，只取成交量 > 0 的分钟。
  - 采集由 `scripts/flow_side_capture.py` 在收盘后完成。范围：现价 ±5%，45 天内的季度/月度/周五到期。
- **报价数据**：同一天的盘中采样、开盘窗、收盘窗报价（有合约才有）。

## 3. 主动方分类（写死）

每个成交分钟：
1. **报价规则**：若 ±2 分钟内有该合约买卖价都有效的报价：分钟收盘价 > 中价 → buy，< 中价 → sell，等于中价 → 转用第 2 条。
2. **tick 规则**：与前一个成交分钟的收盘价相比，涨 → buy，跌 → sell，持平 → 沿用前一分钟的分类；当天第一个成交分钟不分类。

合约当天的 `buy_share` = 买方成交量 /（买方 + 卖方成交量）。
- `buy_share ≥ 0.6` 记 buy，`≤ 0.4` 记 sell，介于两者之间记 mixed。0.6 / 0.4 是未校准的设计值。
- 已分类的成交量为 0 → unknown。

## 4. 报告内容（描述性，不做检验）

- **一致率**：已标 buy/sell 的合约中，推断方向与成交主动方一致的比例。另报按 F 权重 |ΔOI×Δ| 加权的一致率。
- **相关性**：`delta_adj_pp` 与 `buy_share − 0.5` 的符号一致率。
- **覆盖**：F 权重中有逐分钟数据的份额；mixed 与 unknown 的数量；报价规则与 tick 规则各占多少。
- 按品种、按交易日分列，逐日累积，**不挑日子**。
- **什么时候下结论**：至少 10 个交易日、已分类合约 ≥ 200 之前，只描述、不下结论。

## 5. 已知局限（与结果一起呈现）

- 分钟收盘价不是逐笔成交；在分钟收盘价上用 tick 规则分类很粗。
- 报价每 15 分钟采样一次，只到 13:00，大部分分钟只能用 tick 规则。
- 主动方不等于开仓或平仓：主动买入也可能是在平空头。
- 这里只验证 ETF 期权上的推断。COMEX 期货期权是另一个市场，我们没有它的数据（CME 数据不合法可得）。
- 即使一致率高，也只说明推断方法与成交主动方吻合，不说明 F 层能预测价格方向。后者在方向族 D 的冻结检验里另行评估。
