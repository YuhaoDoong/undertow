## 拿到源码前，我的实现错在哪

对着源码逐条比，五处实质偏差：

| | LuxAlgo 源码 | 我的旧实现 |
|---|---|---|
| 默认显示对象 | Order Blocks（`showFairValueGapsInput = false`） | 全用 FVG |
| 订单块定义 | 摆动点→突破点之间 `parsedLow` 最低那根的完整 high~low | 最后一根反向 K 线的实体 |
| 高波动过滤 | 真实波幅 ≥ 2×ATR(200) 的 K 线把 high/low **对调** | 无 |
| 摆动检测 | `leg()` 状态机，单侧确认 + 状态切换 | 左右各 n 根的双侧 pivot |
| 失效判定 | 默认 HIGHLOW，用 high/low 越过边界 | 收盘价 |

**根本错误是第一条**：用户截图上那些色块根本不是 FVG，FVG 在 LuxAlgo 里默认关闭。

第三条是源码里最巧的一手：

```pine
highVolatilityBar = (high - low) >= 2 * atr(200)
parsedHigh = highVolatilityBar ? low : high    // 对调
parsedLow  = highVolatilityBar ? high : low
```

对调后那根的 `parsedHigh` 变得很小、`parsedLow` 变得很大，在取 max/min 时永远选不中。
异常放量的长影线就这样被排除在订单块之外，一行代码不写 if。

## 我们有意偏离源码的地方

用户 2026-09-03：「不用完全照搬，要用最适合我们的。每个技术指标，都是技术面大模块里的一个子模块。」

1. **按方向各取 2 个，而非取最近 5 个**。源码 `orderBlocks.slice(0, maxOrderBlocks)`
   取最近 N 个；实测 GLD 最近 5 个里 4 个是需求区，上方参考位全没了。
   我们要上下各几个参考位 —— 与「找墙取最近三道」同构。
2. **size 用 (5, 20) 而非 (5, 50)**。源码的 Swing length 50 是给 TradingView
   完整历史用的；我们只有 200 根 4H（约 4 个月），size=50 全窗口只产出
   1 个摆动点、0 个订单块。size=20 能产出 5 个，是这个数据量下的结构级替代。
3. **去重**。同一根 K 线可能被多个摆动点选中，源码靠画图覆盖掩盖了这点，
   我们要出数值必须按 (bias, idx) 去重。

## 顺带揪出的线上 bug

校准过程中发现研报的现货换算比值是 `real_price / curr.spot` ——
`real_price` 是 Yahoo 的**实时**期货报价，`curr.spot` 是 ETF 的**前一日收盘**，
两者差一个隔夜。实测把 GC÷GLD 从真值 10.840 推到 11.104（+2.4%），
4H 结构区 GLD 429.39 被显示成现货 4768，而真值是 4655 —— 差 113 点。

这个比值换算研报里**所有**位点，不只是结构区。已改为取期货序列里
today 之前最后一根收盘，与 ETF 前收同日。回归测试见
`tests/test_smc.py::test_研报比值不得用实时期货价除以ETF前收`。

实测 GC÷GLD 最近 14 个交易日：中位数 10.901，区间 10.835~10.959。

## ⛔ 不得用于给期权墙加权

2026-09-03 实测：

- 墙落在同向结构区的比例 put 68% / call 72%，同距离的随机非墙行权价是 62% / 81%
- 按缓冲与 DTE 分层后，区内区外破墙率差异小于层内噪声，且方向不一致
- 找不到「同日同 DTE、缓冲差 <1pp」的配对（0 对）：
  「落在结构区」与「缓冲小」共线到无法分离

根因：两者不是独立信息源，持仓本来就跟着价格走。同源重合是重复计数，不是相互印证。
**正确用法：独立视角展示。**
